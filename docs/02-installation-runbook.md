# F50 256GB 安装操作手册

本文供操作者和 agent 配合使用。先看 [AGENTS.md](../AGENTS.md)，再看本机检查结果。这里的“阶段通过”必须有证据，不能用下一步碰运气。

## 0. 建立工作目录和操作记录

建议把公开代码与本机私密数据放在两个独立目录。私密目录保存设备信息、原厂备份、下载包校验、写入计划、读回结果和账号信息；不要在它上面 `git init` 或 `git add .`。

每个阶段记录：来源 URL、上游 commit/tag、当前系统、当前槽位、目标文件/分区、预计长度、源 SHA256、写入后 SHA256、结果。图形界面显示“成功”不是校验记录。

准备有稳定供电的数据线和 USB 口。需要拔插、输入管理员密码、手机验证时，把操作写清楚交给用户。写入和读回期间不要拔电、不要按复位孔。

## 1. 先确认设备，暂不写入

Windows 安装 Google 官方 platform-tools。驱动缺失时只使用核实来源与签名的驱动。Fastboot 驱动和 Unisoc 下载模式驱动是不同用途。

```powershell
adb devices -l
# 多台设备时，以下每条命令都带 -s <本次目标序列号>
adb -s <SERIAL> shell getprop ro.product.model
adb -s <SERIAL> shell getprop ro.product.board
adb -s <SERIAL> shell getprop ro.build.display.id
adb -s <SERIAL> shell getprop ro.boot.slot_suffix
adb -s <SERIAL> shell id
adb -s <SERIAL> shell su -c id
```

可以使用本仓库 `scripts/preflight.ps1` 把非标识性的检查结果保存到私密目录。它只读，不负责启用调试、提权或安装。

```powershell
# 输出路径的父目录应先存在；脚本拒绝覆盖旧报告。
.\scripts\preflight.ps1 -Serial <SERIAL> -Adb <platform-tools中的adb.exe路径> -OutputFile <私密目录中的preflight.json>
```

检查项：

- 必须确认是 F50/MU300，而不是 F50 Pro、U30 Air 或外观相似机。
- 型号、板型、固件版本、内核、当前启动槽位。
- eMMC 总字节数、逻辑扇区大小、SD 是否存在。Linux 下块设备编号可能因探测顺序变化，应结合 MMC/SD 类型和分区名；不能默认 mmcblk0 永远是内置盘。
- `su -c id` 的真实返回。只有 Magisk APK、图标或 `su` 文件不够。
- GPT 的全部分区范围、主备表一致性、最后一个已用分区的末尾与 last usable LBA。

原厂 USB 端口页面在本案例为 `http://192.168.0.1/index.html#usb_port`。找不到调试接口时先查同固件文档，不猜隐藏 API、不执行不明解锁包。

## 2. 备份是一个独立阶段

先审阅作者的 `tools/backup-device.sh` 和下载工具读取能力，再选择适合本机、能验证的读取路径。无 Root 且无法可靠读取启动/专属分区时，停在刷写之前。临时提权也需要审阅具体范围并取得对应授权。

至少保存：

| 范围 | 原因 |
|---|---|
| GPT 主头、主分区数组、备份数组、备份头 | 记录本机真实容量和布局 |
| A/B 启动相关分区、hardware boot0/boot1、misc | 记录启动链与槽位状态 |
| system/super 及固件相关分区 | 尽可能保留匹配的原厂系统组合 |
| 本机 NV、IMEI 所在区、校准、persist 等 | 别人的 ROM 无法替代 |
| Wi-Fi 配置、需要保留的用户文件 | 用户明确选择需要的内容 |

userdata 很大时，可以在告知限制后不做整个用户分区镜像。本例选择清空个人数据，不代表别人也同意。每个 dump 检查长度、设备源哈希、暂存文件哈希、电脑文件哈希；大文件不能经由文本管道。Windows 的 PTY 和文本重定向可能把 LF 改成 CRLF，二进制镜像应使用不会分配 PTY的通道，并对结果做 SHA256。

离线 GPT 可使用 `scripts/check-gpt.py` 检查。脚本只验证所提供的主/备捕获文件，不连接设备，也不会输出可直接执行的写盘命令。

```sh
# primary.bin 必须从 LBA 0 开始并覆盖主头与数组；secondary.bin 必须覆盖备表并结束于磁盘最后一个 LBA。
# 数值从本机获取，不从本文复制。捕获窗口可以比 GPT 实际结构大。
python scripts/check-gpt.py --primary /private/primary.bin --secondary /private/secondary.bin --disk-bytes <本机总字节数> --sector-size <本机逻辑扇区大小>
```

## 3. Root / 启动环境：不要把本案例固件链泛化

本案例原 B06 未解锁。一次标准 Fastboot 解锁未解决问题，之后经用户单独确认才使用 [作者 F50 工具包](https://github.com/dikeckaan/zte-f50-toolkit) 的 B09 配套流程。

执行前先形成清单：哪些 A 槽启动链、系统、基带镜像需要一起更换；哪些本机专属分区必须保留；哪些数据会清掉；怎样进入下载模式；下载模式读取是否已经验证。

不要把工具包目录中的全部文件逐一刷进去。特别是来自打包设备的 miscdata、ztepersist、metadata 密钥和 NV/校准，不能因为文件名相同就覆盖本机。GPT 也必须保留本机容量，不能导入 32/64GB 设备的表。

本案例用配套 B09、配套 TrustOS 和 Magisk boot，不反复写已验证成功的镜像。每个实际写入范围读回后才能继续。需要恢复 Android 数据时，先确认工具到底是擦分区还是设置 Recovery wipe 请求，以及它是否连带影响 FRP。

Magisk 本例为 28103。配套启动镜像缺运行环境时，补齐**同版本官方文件**并验证哈希，必要时执行已审阅的官方修复流程。ADB shell 的长期 Root 授权单独确认，并在完成后验证 UID 0 和重启持久性。禁止删掉安装器的 Root 检查来绕过去。

## 4. 选择 Linux 的存储位置

优先顺序：已明确允许清空的 SD → 经过确认的内部未分配空间 → 经单独确认的数据分区缩减。

别用 `df` 的 free 当 GPT 的 free。本例内部盘 490831872 个 512 字节扇区，原 userdata 已经靠近磁盘尾部，所以没有可直接用的安装区。256GB 并不意味着天然空出了一大块。

缩分区前必须列出新旧边界、保留分区、对齐方式、GPT 校验步骤与恢复限制。本文不发布一组供复制执行的 `dd seek` 或 `parted` 写入命令。

本机仅从 userdata 尾部让出 4GiB，起点与其他 74 个分区不动。写备份 GPT、读回校验，再写主 GPT、读回校验；两份 CRC 和布局均验证。

**接下来还要验证文件系统。** 本例 GPT 成功后，F2FS 仍是旧大小。只有 Recovery 真正按新边界重建后，F2FS 的 block_count × block_size 才等于新 userdata 大小。未通过这个检查，禁止往尾部安装 Linux。

安装区还需避开备份 GPT、按作者对齐方式计算，并证明没有旧数据需要保留；任何探测偏移都要先证明在设备范围内。旧版安装器的越界探测问题见上游 #65 / #69。

## 5. 安装前固定版本并审阅计划

使用作者 release 的内核和 rootfs，核对其 SHA256SUMS。预先阅读 `install.ps1` / `install.sh`、设备端安装脚本和启动镜像构建器；保留本次实际使用的 commit。不要混用不同日期的内核模块和 Image。

本案例选择 `openwrt-luci`、5.4.254、内部约 4GiB 区域。适合本机不代表未来所有 F50 都应固定这版；如选择新版，先阅读已知问题和对应硬件测试。

先运行作者检查/准备阶段，确认：

- 来源是本机 Android 的 vendor/固件子集。
- Linux 目标不是 Android 当前 boot 槽。
- 目标根文件系统区域有边界、容量和空闲证据。
- 后台账号、Wi-Fi 导入、回退次数已经明确。
- 将写的 boot、misc 范围与对应备份已列出。

最终写入和启动槽位修改需要本次确认。安装器写完后不要马上宣称联网完成。

## 6. 每次写入后校验

镜像做全写入范围的长度和 SHA256；misc 校验实际更新的 32 字节；根文件系统可卸载/重新挂载后按清单核对普通文件与符号链接。本例验证了 1720 个文件和 298 个链接。

注意：本项目 boot 镜像中的一段空间用于保存运行日志。启动后整个 boot_b 的 SHA 变化不一定说明镜像损坏。本例日志区为 48–56MiB，核对前先读本次构建元数据和启动脚本，再比较不变的范围。不能看见整分区哈希变了就重刷。

## 7. 从局域网到互联网逐层验收

1. USB 枚举、DHCP 地址、网关、ARP。
2. SSH 和后台完成真实认证，MU300 页面可访问。
3. Wi-Fi 关联、拿到地址、访问后台。
4. 调制解调器：卡状态、RF、注册、PDP、实际网卡、地址和路由一致。
5. F50 自己通过运营商 DNS 解析，蜂窝 RX/TX 增长。
6. 电脑绑定 F50 USB 源地址和接口，完成外部 DNS、TLS 验证及 HTTP 响应，排除电脑其他网络。
7. 手机关闭移动数据，验证两个网站或应用，持续使用约一分钟。
8. 普通重启、完全断电再启动后重复关键测试。
9. 条件允许时切回 Android，再回来；留下完整说明。

第 4 步的 `CONNECT` 不可以替代第 5–8 步。本机就是在这里卡住，最终按 [故障文档](03-troubleshooting.md) 解决。

## 8. 交付与以后升级

把当前系统/默认系统、后台地址、账号信息、Wi-Fi、备份位置、切换命令、改过的文件及校验值交给用户。秘密单独保存在用户本地。

升级前检查新版本是否包含已有修复。保留本机适配差异，不能把本仓库“一台成功”当作未来版本也自动兼容的保证。代理配置在基础网络全部验收后再做，方便区分蜂窝故障和代理故障。
