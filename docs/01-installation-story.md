# 我让 Codex 给 F50 256GB 装 OpenWrt，真正花时间的是刷完以后

我手里有一台中兴 F50，256GB 存储版。平时插着 SIM 卡当随身 Wi-Fi，用起来没什么问题。看到有人把 F50 装成 OpenWrt，还保留 Android 双系统，我也想试试：硬件已经有了，让 Codex 按项目文档操作，能不能少踩一点坑？

最后确实装好了。手机连它的 Wi-Fi 能上网，电脑通过 USB 也能上网，拔电再插回去会自动恢复。不过中间并不顺利。我原本以为难点在解锁和刷系统，实际最折腾的是最后那一步——OpenWrt 已经运行，Wi-Fi 能连，蜂窝也显示拿到了 IP，就是上不了网。

这里把过程写全。涉及我的设备标识、密码、订阅和备份的部分不会公开。文中的容量是这台机器的实测值，不是给其他机器抄的刷写参数。

## 一开始就搞错了：我并没有插 SD 卡

最初交给 Codex 的要求里写了“已插入一张可以清空的 SD 卡”。后来聊到安装位置，我才发现这句话不对。我实际上只用 USB 接了 F50，根本没插 SD 卡。

Windows 当时出现一个大约 228GB 的共享盘，我还问了一句：没必要把这 256GB 都完整备份吧，里面有用的东西很少。

这个盘不能当作“已经插了 SD 卡”的证据，也不能直接当作可供 Linux 使用的空闲磁盘。它是 Android 提供出来的文件共享视图。安装 OpenWrt 要看的，是设备真实的块设备和 GPT，而不是 Windows 资源管理器显示还剩多少空间。

## 都叫 F50，64GB 参考布局不能直接套到 256GB

项目最常见的参考机是 64GB F50。那台机器在 Android 分区后面有一块未分配空间，可以把 Linux 放进去，不动 Android 的数据分区。

我这台虽然容量更大，却不是同样的情况。实际读取到的内部存储为 251305918464 字节，GPT 的 userdata 已经占到了接近磁盘末尾。Android 里“还有很多可用空间”，和“分区表后面还有未分配空间”，是两回事。

所以，256GB 并没有让我省掉存储准备这一步。没有 SD 卡，也没有可直接用的尾部空闲区，最后只能在我确认清空 Android 数据后，从 userdata 末尾让出约 4GiB。

我中途也提出过疑问：这些容量版本按理说系统应该差不多，只是 Flash 大小不一样，为什么不能通用？现在回头看，系统主体可能兼容，但安装器要写哪里，必须按本机分区表计算。这个区别真的不能省。

## ADB 不是电脑弹了授权就算打开

一开始电脑能认到 F50，但 `adb devices` 是空的。我允许了电脑端弹出的提示，ADB 还是没有设备。

原厂后台的常规菜单里也找不到 USB 调试。最后是在原厂后台的 USB 端口页面打开调试接口：

```
http://192.168.0.1/index.html#usb_port
```

登录后选择打开并应用，ADB 才出现。这里的前提是我的这版固件确实提供这个页面；不能把路径当成所有 F50 都有的万能入口。

设备随后确认是 F50 / MU300，板型 `ums9620_2h10_feimao`，原固件 F50SPV1.0.0B06，Android 13，当前在 A 槽。我之前没有 Root、没有解锁，也没用过 ADB。

## 备份没有把整个 256GB 拷下来

我允许清空 Android，所以没有去备份整个 userdata。真正先保存的是系统和恢复需要的内容：除 userdata 外的 74 个命名分区、eMMC 的 boot0/boot1、主备 GPT，以及本机自己的 NV、校准等专属数据。能读到的 Wi-Fi 配置也单独保留了。

最终这些备份大约 5.86GiB，而不是 256GB。每份文件都核对长度和 SHA256；GPT 还验证了主备头、分区表 CRC 和分区边界。

但我没有把“有备份”理解成“随时能一键恢复”。备份不含 Android 应用和个人文件，也不含 RPMB、eFuse 等无法按普通分区复制的内容。完整故障恢复没有实际跑过。后面如果分区布局改变，更不能直接把旧 GPT 写回去就算恢复了。

## 标准解锁没走通，最后还是回到作者配套流程

中间试过一次原厂 `fastboot flashing unlock`。这是在单独说明会影响启动验证、可能清数据之后，我才确认允许的。它没有解决问题，也没有继续穷举各种 unlock 命令。

后来按作者工具包的 B09 配套方案处理：先核对本机和工具包，再替换匹配的系统、启动链和基带相关镜像，清理需要重建的数据。包里的设备专属数据没有拿来覆盖本机。每个写入范围都读回校验，没有因为没成功就连续重刷 TrustOS。

这一步确实有风险，并不是“装 OpenWrt 只写 B 槽”那句话能够概括的。Linux 安装本身和之前为了获得可用 Root/启动环境而做的固件替换，是两段不同的操作。我的 Android 后来变成了工具包配套的 B09，不再是最初的 B06。

接着写配套 TrustOS 和 Magisk 启动镜像。Magisk 也不是镜像写完就能用：这台机器缺少配套运行文件，需要补齐官方 28103 的运行环境，并且单独允许 ADB shell 使用 Root。文件版本和哈希匹配后，再用 `su -c id` 验证确实是 UID 0。

如果当时为了继续安装，把 Root 检查删掉或者假装成功，后面的分区操作就完全没有可信基础了。

## 缩了分区，文件系统却没跟着缩

存储准备是另一个大坑。我确认允许从内部存储让出 4GiB 后，按作者流程调整了 userdata 的末尾，其他分区起点和位置保持不变，主备 GPT 分别写入、分别读回，并验证 CRC。

分区改完，看起来已经有地方装 Linux。但继续检查发现：userdata 分区是约 224.19GiB，F2FS 文件系统仍认为自己是原来的约 228.19GiB。

这时候不能继续往尾部写 OpenWrt。否则两边以为自己拥有同一段空间，后果可能过几次启动才出现。

作者流程里的清零开头并没有在我这台机器上完成预期重建。我又确认了一次数据清除，才执行作者下载工具对应的 Recovery 恢复出厂流程。这里还专门核对了工具实际干什么：它不是简单把 userdata 全盘写零，而是向 Recovery 写入清数据请求，还会涉及 metadata 和 FRP。

处理完成后，F2FS 的块数乘以块大小，终于等于新的分区大小，约 224.19GiB。确认文件系统不会碰到新让出的区域，才继续安装 Linux。

## OpenWrt 装上了，但第一个晚上并不能用

最终选择的是带 MU300 管理面板的 OpenWrt 25.12.5，项目 v2026.10.11，配厂商 5.4.254 内核。Linux 放在新腾出的内部区域，Android 留在 A 槽，Linux 启动镜像放在 B 槽。

安装不是看到一行 success 就结束。写入后重新挂载核对了 1720 个普通文件、298 个符号链接，启动镜像和 misc 选择槽位的 32 字节也做了读回检查。原来的 Wi-Fi 名称和密码恢复到了 OpenWrt。

第一次启动后，手机能看到 Wi-Fi，但点连接失败，设备还亮了红灯。电脑端也出现过拿到地址却进不了 SSH 和后台的情况。

最后通过串口看到防火墙报错：

```
flowtable ft: Resource busy
flow offload @ft: No such file
```

这个 5.4 内核的软件流量加速让 fw4 重载失败，LAN 规则没有完整生效。修复是关闭软件 flow offloading，重新加载防火墙，再检查真实生效的规则。没有关闭整个防火墙。

修复之后，手机终于能连 Wi-Fi，DHCP 正常，后台和 SSH 也能用了。我当时以为快结束了。

## Wi-Fi 能连，蜂窝有 IP，还是没有互联网

接下来这一段最容易误判。OpenWrt 能注册运营商，拨号返回 `CONNECT`，WAN 有地址，默认路由也有，但接收计数始终是零。手机提示无法访问互联网，电脑通过 F50 的 USB 发起 DNS 和 HTTPS 请求也失败。

我还观察到过短暂能上网，所以专门补充了这个信息。后来验证时，都要求手机关闭自己的移动数据；电脑的测试也绑定到 F50 的 USB 接口，避免从别的网卡、热点或代理绕出去。

切回保留的 Android 后，同一台设备、同一张卡又可以上网。这说明至少硬件和套餐不是整个坏了，问题集中在 Linux 的初始化和数据路径。

## 外插物理卡，不代表一定是逻辑 slot 0

项目原脚本默认使用 nr1/nr2 和 sipa_eth0。我的 Android 实际把这张外插卡放在逻辑 slot 1，数据网卡是 sipa_eth8，原厂 RIL 发命令的通道是 nr4。

我中间还强调过“我也是物理 SIM 卡”。现在文档里必须把这件事写清楚：外插、内置是对卡位置的描述，slot 0/1 是这台基带的软件编号，不能仅凭名字互相推导。

Codex 据此做了本机最小适配，让 AT 查询、拨号、网卡和面板指向一致的逻辑卡槽。这里也踩过坑：最初把 `SMMSWAP` 的参数当作卡槽号改了，导致 AT 异常；检查本机原厂 RIL 后恢复了固定的 `AT+SMMSWAP=0`。这不是可以靠名字猜含义的命令。

后来又修正了 IPA 加载前的查询通道，让它确实检查正在使用的那张卡，而不是检查空的 slot 0。SIM 能识别、能注册、能拨号了，接收仍然是零。

## 没有效果的尝试，也要留下结论

为了定位，做过几次有边界的比较：读取本机 Android 的 RIL、观察原厂拨号顺序，比较 IPA 驱动状态，检查是否有 VPN 遗留路由；也试过按本机原厂顺序配置 PDP，以及临时改变 IPA 工作模式。

这些都没有解决最后的下行问题。一次单独确认的 `AT+SPSWITCHDATACARD=1,1` 返回 `CME ERROR: 4`，没有继续换参数反复试。

10 月 8 日晚上我说，最后再试一次，不行就先切回 Android，我要先正常用，周末再整。Codex 按这个要求切回 Android，并设成默认启动。我实际测了 Wi-Fi，电脑也绑定 F50 USB 验证了 DNS、TLS 和 HTTP 200，确认可用后才停。

## 周末再查，社区刚好有了对上症状的修复

10 月 10 日继续，我第一句话就是先看看网上有没有解决方案，没有再自己研究。这次查到了 [PR #72](https://github.com/dikeckaan/mu300-linux/pull/72)。

它描述的现象和我这台非常像：slot 1 已经拿到地址，`CGDATA` 返回 CONNECT，IPA 也正常，却收不到 DNS/TCP 回包。提交者发现，原厂 RIL 还会执行：

```
AT+SPSWDATA
```

这条命令选择分组数据路由。注意，它不是前一次失败的 `SPSWITCHDATACARD=1,1`。

Codex 先审阅 PR，再核对我这台 B09 的原厂 RIL，确实找到同一条命令和对应的数据卡处理路径。没有直接把整个草稿分支或最新系统刷进去，而是在现有 OpenWrt 上做最小验证。

结果非常直接：命令返回 OK，蜂窝接收计数从 0 增到 81，运营商 DNS 立刻开始回答。电脑通过 F50 USB 访问百度和腾讯，都完成了证书校验并返回 HTTP 200。随后我用手机关掉移动数据，连 Wi-Fi 实测，也正常了。

之前 APN 配的是 cmnet，但基带返回的活动 APN 是 cmiot5g，一度看着很可疑。社区实测说明 Android 正常工作时也会这样，不能单凭这点认定 APN 错了。

## 这次不是只在当前会话里能上网

确认有效之后，修复才写进拨号脚本：第二逻辑卡槽必须拿到 CONNECT，接着执行 SPSWDATA 并收到 OK，才继续报告拨号成功。原脚本先备份，替换文件前后都核对 SHA256。

普通重启后，日志显示大约 48 秒完成数据路由设置、50 秒完成蜂窝联网。然后我拔掉 USB，等十秒再插回去，等它启动，手机仍然能上网。电脑的 USB HTTPS、后台登录和 DHCP 也又验证了一遍。

到这一步，我才觉得这次是真的装好了。不是看到 LuCI 页面就说成功，也不是看到信号和 IP 就说完成。

## 我现在保留的使用方式

平时默认进 OpenWrt，Android 还在，需要时可以切回去。Linux 连续五次没完成启动会回退 Android。Wi-Fi 用原来的名称和密码，管理员密码保存在我自己的本地说明文件里，没有放进 GitHub。

安装文档、检查脚本和这份记录可以公开，但每台机器的备份、GPT 原始文件、NV、校准数据和订阅都不能拿来互相复制。以后升级也要先看是否保留这套逻辑卡槽和 SPSWDATA 修复，不能一键升级完再从头找为什么断网。

这次最大的收获其实很具体：让 agent 操作设备，可以让它跑命令、比对文件、查日志，但必须让它把“现在知道什么、还没验证什么”分清楚。容量、Root、文件系统边界和真实联网，每一项都得看本机结果。

## 后记：把 Clash 也放进 F50

基础网络好了之后，我又让 Codex 读取电脑桌面的订阅文件，在 F50 上配 Clash。我选的是国内直连、其他流量走代理，手机只需要连 Wi-Fi，不用自己再开一个客户端。

这次没有为了代理去升级整套 OpenWrt，而是独立安装 Mihomo ARM64 和本地管理面板。先关着 TUN 测节点，Google、YouTube、百度都能访问以后，才开始接管 Wi-Fi 和 USB 流量。

结果又碰到一次 5.4 的兼容问题：自动重定向所需的 Netlink 操作不支持。最终用标准 TUN 策略路由，补上 LAN 到 TUN 的防火墙转发。防火墙没有关，之前修好的 SIM1 脚本也没动。

我关闭手机移动数据和手机上的 VPN 实测了一遍，国内外都正常。重启后，电脑通过 F50 USB 也再次验证通过。跨到 10 月 11 日，我又问能不能升级，核对发现刚装的 v1.19.32 已经是官方最新稳定版，就没有为了“升级”再换一遍相同文件。以后更新代理内核和更新 OpenWrt，可以分开做。
